Modern Java — 9 to 21

Java › lesson 12 of 14 · DEEP — what changed after Java 8, and why

In one line — Since Java 8, the language got shorter and safer: var for less boilerplate, records for data classes, sealed classes to control who can extend, switch expressions + pattern matching to replace clunky if-casts, and text blocks for multi-line strings. This lesson teaches each as "what did it replace, and why?" — your contrast anchor is the Java 8 you already know.

§1Where it fits

This is your explicit post-8 goal. Each feature is an upgrade to something from earlier lessons — records upgrade type-system-and-oop's data classes, pattern matching upgrades polymorphism, virtual threads (lesson 11) upgrade concurrency. Adopt them and idiomatic modern Java reads very differently from 2014 Java.

§2Why it exists

Java 8 code has a lot of ceremony: 40-line "data" classes, casts after instanceof, fall-through switch, escaped multi-line strings. Each modern feature removes one specific pain while keeping full backward compatibility — and the six-month release train (since Java 9) ships them steadily, with LTS versions (11, 17, 21) for enterprises to standardize on (Oracle — Java Language Changes).

§3How it works

var — local type inference (10/11)

var list = new ArrayList<String>(); — the compiler infers the type from the right side. It's still static typing (the type is fixed, just not written), only for local variables. Use it when the type is obvious; don't use it when it hurts readability.

Records (16) — data classes without the boilerplate

A record is an immutable data carrier. One line generates the constructor, equals, hashCode, toString, and accessors — the exact "value object" you hand-wrote in lesson 5, now correct by construction. Replaces the 40-line POJO.

Sealed classes (17) — a closed family

sealed lets a type say exactly which classes may extend it (permits Dog, Cat). Now the compiler knows the full set — so a switch over them can be checked for completeness. Together with records, this gives Java algebraic data types (a fixed set of shapes).

Switch expressions + pattern matching (14 → 21)

switch becomes an expression that returns a value with arrow labels and no fall-through. Pattern matching for instanceof removes the redundant cast; for switch (21) it lets you branch on type and shape; record patterns destructure a record inline. Together they replace towers of if (x instanceof Y y) ….

Text blocks (15)

"""… """ spans multiple lines with no \n or + — ideal for JSON, SQL, HTML.

§4When to use

  • records — DTOs, value objects, map keys, method return tuples. Default for "just data."
  • sealed + records + switch patterns — modelling a fixed set of cases (states, events, AST nodes).
  • switch expression — mapping an input to a value; safer than statement switch.
  • var — obvious local types; keep explicit types on public APIs.
  • text blocks — any embedded multi-line literal.

§5Explain it to a 12-year-old

Old Java made you write a long form every time you described a simple thing — name, address, phone — even though it's always the same form. A record is a stamp that fills the whole form for you. A sealed class is a club with a posted guest list: only named people get in, so the bouncer (compiler) can be sure nobody's missing. And the new switch is a smart sorting hat that looks at what something is and hands back the right answer in one line.

§6Connections

  • ← type-system-and-oop: records = the value object done right; sealed = controlled inheritance.
  • ← collections-and-equality: a record's auto equals/hashCode makes it a safe key.
  • ← concurrency: immutable records are naturally thread-safe; virtual threads (21) sit here too.
  • → application-architecture: sealed + records model your domain precisely and make illegal states unrepresentable.
  • Same idea elsewhere: Kotlin data classes, Scala case classes, TypeScript discriminated unions — Java caught up.

§7In practice — before vs after

Illustrative — these features need JDK 16/17/21; your machine runs JDK 1.8, so this is shown for contrast, not run here. Compile with javac --release 21 on a modern JDK.

// Java 8: a value object by hand — ~30 lines of constructor/equals/hashCode/toString
final class Point { final int x,y; /* + ctor + 3 overrides + getters */ }

// Modern: one line, all of it generated and correct
record Point(int x, int y) {}

// Sealed family + switch pattern matching + record destructuring (21)
sealed interface Shape permits Circle, Rect {}
record Circle(double r) implements Shape {}
record Rect(double w, double h) implements Shape {}

static double area(Shape s) {
    return switch (s) {                       // an EXPRESSION, returns a value
        case Circle(var r)    -> Math.PI * r * r;  // destructure inline
        case Rect(var w, var h) -> w * h;
    };                                          // no default needed — sealed = compiler knows all cases
}
Notice what disappeared: the hand-written boilerplate, the instanceof+cast, the fall-through breaks, and even the default branch — because sealed tells the compiler the case list is complete. If you later add a Triangle, the switch stops compiling until you handle it. That's illegal states becoming compile errors.
Predict. On the sealed Shape above, remove the Rect case from the switch. Does it compile? (Hint: an exhaustive switch over a sealed type must cover every permitted subtype — the compiler rejects the gap.)

§8Pitfalls

Overusing var. var x = foo(); where the return type is unclear hurts readability. Prefer it only when the type is obvious.
Records aren't for everything. They're shallowly immutable and can't extend a class. Not a replacement for rich entities with behaviour.
Preview features. Some features shipped as "preview" first (needing --enable-preview). Check what's final in your target LTS.
Module system friction. JPMS (9) is powerful but adopting it mid-project is disruptive; many apps stay on the classpath.
Chasing latest. Target an LTS (17 or 21) for production stability, not the newest six-month release.

§9Recap

  • var = inferred local types, still static typing; use when obvious.
  • records = one-line immutable value objects with correct equals/hashCode/toString.
  • sealed = a fixed, compiler-known set of subtypes; enables exhaustive checks.
  • switch expressions + pattern matching replace instanceof-cast towers and fall-through.
  • record patterns destructure data inline; text blocks handle multi-line strings.
  • Target an LTS (11/17/21); learn each feature as "what did it replace, and why?"

Glossary

var
Local-variable type inference; the compiler fills in the type.
record
Compact immutable data class with generated members.
sealed
A type that lists exactly which classes may extend/implement it.
switch expression
A switch that yields a value, arrow-style, no fall-through.
pattern matching
Test type/shape and bind a variable in one step.
record pattern
Destructure a record's components inside a pattern.
text block
A """-delimited multi-line string literal.
LTS
Long-Term-Support release (11, 17, 21).
