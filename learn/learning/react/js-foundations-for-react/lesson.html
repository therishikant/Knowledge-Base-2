JavaScript Foundations for React

The handful of modern-JavaScript features React leans on constantly — so React code reads as React, not as unfamiliar JS.

Summary. React is just JavaScript. Before the framework makes sense, you need fluency in ~10 modern JS features it uses everywhere: const/let, arrow functions, closures, destructuring, spread, map/filter, template literals, ternary/&&, ES modules, and immutability. This lesson is that toolkit — plus a quick look at the DOM, the thing React exists to manage for you.

§1Where it fits

This is subtopic #1 on the React overview — a skim, base-language stop before we touch React itself. As a Java developer you already know programming; what you're rusty on is this language's dialect. React doesn't invent much syntax — it borrows JavaScript's and expects you to be comfortable with it. Every later subtopic (components, props, hooks) is these features in a trench coat. Nail them here and React stops looking like magic soup.

§2Why it exists (why this JS, and why now)

JavaScript is the only language browsers run natively — so any front-end framework is ultimately JS. "Modern JS" (ES2015 / ES6 onward, 2015+) added the ergonomic features React's style depends on: arrow functions for concise callbacks, destructuring for pulling values out of objects, modules for splitting code into files, and array methods for transforming data into UI. Older JS could do all this, but clumsily. React's idioms assume the modern versions.

Java bridge. Think of this like moving from Java 7 to Java 8: lambdas (a -> a+1) ≈ arrow functions; Stream.map/filter ≈ array .map()/.filter(); var type inference ≈ const/let. Same ideas you already use — different spelling.

§3How it works — the core toolkit

3.1 Variables: const and let (never var)

const name = "Ada";   // can't be reassigned  → default choice
let count = 0;        // can be reassigned
count = count + 1;    // fine
// name = "Grace";    // ✗ TypeError: Assignment to constant variable

Prefer const; reach for let only when you must reassign. const stops the variable being rebound — but an object it points to can still be mutated (more on that in §3.9).

3.2 Functions & arrow functions

// classic function declaration
function add(a, b) { return a + b; }

// arrow function — concise, expression-bodied
const add2 = (a, b) => a + b;        // implicit return, no braces
const square = n => n * n;           // one param → parens optional
const greet = () => "hi";            // no params → empty parens

// arrow with a body needs an explicit return
const addLogged = (a, b) => {
  console.log("adding");
  return a + b;
};

Arrow functions are the workhorse of React callbacks (onClick={() => ...}). The => is JS's lambda arrow, exactly like Java's ->.

React: a component is a function that returns markup, and event handlers are almost always arrow functions. You'll write hundreds of these.

3.3 Closures — why hooks work

function makeCounter() {
  let count = 0;                 // "captured" by the inner function
  return () => {                 // this arrow "remembers" count
    count = count + 1;
    return count;
  };
}
const next = makeCounter();
next(); // 1
next(); // 2  ← the inner function kept access to `count`

A closure is a function that "remembers" variables from where it was created, even after that outer function has returned. This is the mechanism behind React hooks: useState hands your component a value and a setter, and your event handlers close over them.

3.4 Objects & arrays

const user = { name: "Ada", role: "admin" };   // object (like a Map/POJO)
user.name;          // "Ada"  — dot access
user["role"];       // "admin" — bracket access

const nums = [10, 20, 30];   // array (ordered list)
nums[0];            // 10
nums.length;        // 3

3.5 Destructuring — unpacking

const user = { name: "Ada", role: "admin" };
const { name, role } = user;        // pull fields into variables
// name = "Ada", role = "admin"

const nums = [10, 20, 30];
const [first, second] = nums;       // first = 10, second = 20
React: you'll see this constantly — function Button({ label, onClick }) destructures props, and const [count, setCount] = useState(0) destructures the array useState returns.

3.6 Spread ... and rest

const a = [1, 2];
const b = [...a, 3];                // [1, 2, 3]  — copy + add (spread)

const base = { name: "Ada", role: "user" };
const promoted = { ...base, role: "admin" };  // {name:"Ada", role:"admin"} copy + override

function sum(...nums) {              // rest: gather args into an array
  return nums.reduce((t, n) => t + n, 0);
}
sum(1, 2, 3); // 6

Spread makes a shallow copy. This is how you update React state immutably (§3.9) — you build a new object/array instead of mutating the old one.

3.7 Array methods: map, filter, reduce

const nums = [1, 2, 3, 4];

nums.map(n => n * 2);          // [2, 4, 6, 8]   — transform each item
nums.filter(n => n % 2 === 0); // [2, 4]         — keep items passing a test
nums.reduce((t, n) => t + n, 0); // 10           — fold to a single value
React: .map() is how you turn an array of data into a list of UI elements — items.map(item => <li>{item.name}</li>). It's the single most-used array method in React.

3.8 Template literals, ternary, and &&

const name = "Ada";
const msg = `Hello, ${name}!`;      // template literal (backticks, ${})

const isAdmin = true;
const label = isAdmin ? "Admin" : "User";   // ternary: cond ? a : b

const show = true;
show && "visible";                  // short-circuit: right side only if left is truthy
React: there's no special template syntax for conditions — you use plain JS. Ternary and && are how you conditionally render UI. (react.dev, Quick Start — Conditional rendering)

3.9 Immutability — the mindset React demands

// ✗ mutation — changes the existing array/object in place
const arr = [1, 2];
arr.push(3);          // arr is now [1,2,3]; SAME array reference

// ✓ new value — leaves the original alone
const arr2 = [...arr, 3];        // brand-new array
const obj2 = { ...obj, done: true }; // brand-new object

React decides whether to re-render partly by checking "is this a new object?" (reference identity). If you mutate in place, the reference is unchanged and React may miss the update. So you always produce new values. This is the same discipline as Java's immutable objects / defensive copies.

3.10 ES modules: import / export

// math.js
export function add(a, b) { return a + b; }   // named export
export default function App() { /* ... */ }    // default export (one per file)

// main.js
import App, { add } from "./math.js";          // default + named
import { useState } from "react";               // from a package

Every React file is a module. import React from "react", export default your component. Like Java's package + import, but per-file.

3.11 A little async (for later effects/data-fetching)

// a Promise represents a future value
async function loadUser(id) {
  const res = await fetch(`/api/users/${id}`); // await pauses until resolved
  return await res.json();
}
loadUser(1).then(user => console.log(user));

You don't need mastery yet — just recognize async/await and Promise. They return when we hit useEffect and data fetching.

3.12 The DOM — the thing React manages for you

The browser turns your HTML into a live tree of objects called the DOM (Document Object Model). JavaScript can read and change that tree, and the screen updates to match. This is what React sits on top of. 

// raw DOM — imperative: you find nodes and mutate them by hand
const btn = document.createElement("button");
btn.textContent = "Clicked 0 times";
let count = 0;
btn.addEventListener("click", () => {
  count++;
  btn.textContent = `Clicked ${count} times`; // you manually update the DOM
});
document.body.appendChild(btn);

§5Explain it to a 12-year-old

Imagine building with LEGO. The DOM is the model you've already snapped together on the table. The old way (raw JavaScript) is: every time something changes, you crawl over the model, find the exact bricks to swap, and swap them by hand — easy to miss one. React is like handing a friend a picture of how the model should look now; the friend figures out which bricks to change and does it for you. But to draw that picture, you need a pen — and these JavaScript features (map, arrow functions, spread…) are the pen. This lesson is learning to hold the pen before we draw.

§7In practice — code dissection

Here's a single snippet that uses almost every feature above, the way React code does. Dissected chunk-by-chunk.

// 1. a module importing a helper
import { formatPrice } from "./money.js";

// 2. some data
const products = [
  { id: 1, name: "Cabbage", price: 1.5, inStock: true },
  { id: 2, name: "Garlic",  price: 0.9, inStock: false },
  { id: 3, name: "Apple",   price: 2.0, inStock: true },
];

// 3. a function that takes options via a destructured object
function listInStock(items, { maxPrice }) {
  return items
    .filter(p => p.inStock && p.price <= maxPrice)   // 4. keep matching
    .map(p => {                                        // 5. transform each
      const { name, price } = p;                       // 6. destructure
      return `${name}: ${formatPrice(price)}`;         // 7. template literal
    });
}

const cheap = listInStock(products, { maxPrice: 1.6 });
console.log(cheap);

1 module import — every React file starts like this.  2 an array of objects — exactly the shape a component renders.  3 the second argument is a destructured options object (React reads props this way).  4 filter + && narrows the list.  5 map transforms — in React this would return JSX, not strings.  6 destructuring inside the callback.  7 a template literal builds the output. Swap the strings in 5 for <li>...</li> and you've basically written a React list.

§8Pitfalls

Mutating instead of copying. arr.push(x) / obj.x = 1 mutate in place — React may not notice. Build a new value with spread instead. This is the #1 React-state bug.
Confusing =, ==, ===. Always use === (strict equality). == does surprising type coercion (0 == "" is true).
&& with numbers in JSX. count && <X/> renders a stray 0 when count is 0, because 0 is falsy but still printable. Prefer count > 0 && .... (You'll hit this in conditional rendering.)
Forgetting arrow functions capture the surrounding scope. That's usually what you want in React — but it means a handler "remembers" the values from its render (closures again).

Glossary

Arrow function
Concise function syntax (args) => expr; JS's lambda.
Closure
A function that remembers variables from where it was defined, even after the outer function returns.
Destructuring
Syntax for unpacking values from objects/arrays into variables.
Spread (...)
Expands an array/object's contents; used to make shallow copies.
Immutability
Never changing a value in place; producing a new value instead.
Module
A single JS file that exports/imports values.
DOM
Document Object Model — the browser's live object-tree of the page that JS can manipulate.
Promise
An object representing a value that will be available later (async work).

§10Recap — active recall

  • React is just JavaScript; these ~10 features are its whole dialect.
  • const by default; arrow functions everywhere; === not ==.
  • .map() renders lists; .filter() narrows them; ternary/&& render conditionally.
  • Destructuring reads props and the useState pair; spread makes the new values React needs.
  • Never mutate state — copy with spread. #1 React bug avoided.
  • Closures are why hooks can "remember" — comes back in state & hooks.
  • The DOM is the tree React updates for you; raw JS makes you update it by hand.
