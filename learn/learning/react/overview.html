The 30-second picture

React is a JavaScript library for building user interfaces out of components — reusable pieces of UI that are just JavaScript functions returning markup. Its defining idea is being declarative: you describe what the UI should look like for the current data, and React figures out how to update the actual page to match. "React apps are made out of components ... a component is a piece of the UI that has its own logic and appearance" (react.dev, Quick Start).

The whole game — the thing that makes React worth learning — is understanding the machinery it runs for you: when your data changes, React re-runs your component functions, builds a lightweight description of the UI (the Virtual DOM), diffs it against the previous one, and applies only the minimal real-DOM changes. That single decision — a virtual layer between your code and the browser's DOM — is the root of almost every trait we'll study: components, one-way data flow, state, hooks, and re-rendering.

Contrast anchor (base language = raw JS + DOM). Without React you'd hand-write document.createElement, element.appendChild, and manual textContent = ... updates, carefully mutating the page every time anything changes — imperative UI. React replaces that hand-wiring with a declarative model. For every feature we learn, we'll ask: "what would I have to write myself if React didn't exist?"

Why React exists (the problem it removes)

As UIs grow, keeping the screen in sync with ever-changing data by hand becomes a bug factory: dozens of places manually poke the DOM, and it's easy to update one and forget another. React's answer: UI = f(state). Describe the result you want for the current state; let the library reconcile the difference. You get reusable components, predictable one-way data flow (data flows down, events flow up), and updates that are declarative instead of a pile of manual mutations. (react.dev, Thinking in React)

Glossary

Component
A reusable piece of UI written as a JavaScript function that returns markup (JSX).
JSX
An HTML-like syntax embedded in JavaScript; compiled to React.createElement calls.
Props
Read-only inputs passed from a parent component to a child (like function arguments).
State
A component's private, changeable memory; updating it triggers a re-render.
Hook
A special function starting with use that lets a component tap into React features (e.g. useState, useEffect).
Virtual DOM
A lightweight in-memory description of the UI that React diffs against the previous one to compute minimal real-DOM updates.
Reconciliation
React's diffing algorithm that decides what actually changed between two renders.
Render
React calling your component function to produce JSX; distinct from the commit where the DOM is actually changed.
Declarative
Describing what the UI should be for the current data, rather than the step-by-step how of updating it.
One-way data flow
Data flows down through props; changes flow up through event handlers/callbacks.
