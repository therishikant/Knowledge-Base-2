Testing Spring Applications

Spring › lesson 14 of 18 · DEEP — Bootstrapping Only the Boxes You Need

Summary — Testing in Spring is really one simple question: how many of our 6 Boxes do I need to boot up for this test? Most business logic needs 0 Boxes (just call new BookService(fakeRepo) in plain JUnit in 5 ms). Web and database boundaries need 1 Slice Box (@WebMvcTest for Box 6, or @DataJpaTest for Box 3/4 repositories), and only a few end-to-end smoke tests need All 6 Boxes (@SpringBootTest).

§2Why it exists — The Pain Without Slice Testing & Constructor DI

Why do we care so much about how you wire dependencies (Lesson 3) and how much of Spring you boot in a test? Look at what happens when a developer uses @Autowired field injection and puts @SpringBootTest on every test class: 

// ❌ THE PAINFUL WAY: Field injection + booting all 6 Boxes just to test an 'if' statement!
public class BadLoanService {
    @Autowired private BookRepository books;   // Private field! Can't pass a fake in 'new BadLoanService()'
    @Autowired private LoanRepository loans;

    public Loan borrow(long bookId, long memberId) {
        Book b = books.findById(bookId).orElseThrow();
        if (!b.isAvailable()) throw new BookUnavailableException(bookId);
        return loans.save(new Loan(bookId, memberId, LocalDate.now().plusDays(14)));
    }
}

// Because fields are private, the developer boots the ENTIRE Spring container (Boxes 1–6):
@SpringBootTest   // ☠ Boots 150 auto-configs, Hibernate, HikariCP, Tomcat... takes 6,000 ms!
class BadLoanServiceTest {
    @Autowired BadLoanService service;
    @MockitoBean BookRepository books; // Alters the Context Cache key → forces ANOTHER 6,000 ms reboot!
}
The Contrast Anchor: To test a 3-line if (!b.isAvailable()) check, @SpringBootTest ran classpath scanning (Box 2), instantiated 200 singletons (Box 3), generated CGLIB proxies (Box 4), and booted Hibernate. If you have 200 test classes like this, your CI build takes 25 minutes. With Constructor Injection, you don't boot Spring at all—you call new LoanService(fakeBooks, fakeLoans, fixedClock) and it finishes in 2 milliseconds.

§3How it works — Plain Java Data Structures First (Level 1 → Level 2 Zoom)

1. Plain Java Data Structures Inside Spring's Test Engine

Before learning any test annotations, look at the three plain Java data structures that power all of Spring testing:

  • The Context Cache (Map<MergedContextConfiguration, ApplicationContext>): When JUnit runs a Spring test, SpringExtension does not destroy Box 3 (ApplicationContext) when the test class finishes. It stores the live container in a static Map keyed by the test's configuration fingerprint:
    record ContextCacheKey(Set<Class<?>> configClasses, Set<String> activeProfiles, Map<String,String> properties, Set<MockitoBeanDef> mockBeans).
    If Test Class B has the exact same key as Test Class A, contextCache.get(key) returns the already-running Box 3 in 0 ms!
  • Slice Filter (Predicate<BeanDefinition>): A slice annotation like @WebMvcTest is just a filter on Box 2 (Map<String, BeanDefinition>). During scanning, it says: "Is this class a @Controller or @ControllerAdvice? Keep it in Box 2. Is it a @Service or @Repository? Throw its recipe away!"
  • MockMvc (Fake Box 5 Caller): Instead of opening a real TCP ServerSocket(8080) in Box 5, MockMvc creates a fake in-memory MockHttpServletRequest and passes it directly into Box 6 (DispatcherServlet.service(req, resp)) on the same thread.
Step-by-Step Control Flow: What Happens When JUnit Runs a Spring Test
Step 1 (Build Key) → JUnit 5 triggers SpringExtension → inspects annotations (@WebMvcTest, @ActiveProfiles, @MockitoBean) → builds MergedContextConfiguration key.
Step 2 (Cache Check) → Looks up key in static Map<MergedContextConfiguration, ApplicationContext>.
Step 3 (Hit or Miss) → CACHE HIT: reuses existing Box 3 instantly (0 ms).
                     → CACHE MISS: runs Phase 1 Startup for the requested Boxes (only Web beans for @WebMvcTest, only JPA beans for @DataJpaTest, or all 6 Boxes for @SpringBootTest) and puts Box 3 into the Map.
Step 4 (Inject Test) → Injects fields into your JUnit test instance (and resets any @MockitoBean stubs).
Step 5 (Run & Clean) → Runs @Test method. (If @DataJpaTest, wraps Step 5 in a Box 6 ThreadLocal transaction and calls connection.rollback() in an afterEach hook!)

2. Zooming In: The 4 Test Tiers and Which Boxes They Touch

Level 0 — Plain JUnit 5 (0 Boxes Started)

class LoanServiceTest {   // Zero Spring annotations! Runs in 3 milliseconds.

    private final InMemoryBookRepository books = new InMemoryBookRepository();
    private final LoanService service = new LoanService(
            books, new InMemoryLoanRepository(), Clock.fixed(FIXED_INSTANT, ZoneOffset.UTC));

    @Test
    void rejects_borrowing_an_unavailable_book() {
        books.save(aBook().id(1L).unavailable().build());
        assertThatThrownBy(() -> service.borrow(1L, 42L))
            .isInstanceOf(BookUnavailable.class);
    }
}
Hand-written Fake vs Mockito Mock: An InMemoryBookRepository (backed by a simple HashMap<Long, Book>) is often cleaner than writing when(repo.findById(1L)).thenReturn(...) in 40 tests. Use fakes for state (repositories) and mocks for verifying outbound side effects (was the email sender called?).

Level 1A — @WebMvcTest (Box 5 Security Filter + Box 6 DispatcherServlet Only)

@WebMvcTest(BookController.class)           // Filters Box 2 recipes: keeps ONLY BookController + MVC/Security
class BookControllerTest {

    @Autowired MockMvc mvc;                 // Sends fake HTTP request straight into Box 6 DispatcherServlet
    @MockitoBean BookService service;       // Boot 3.4+ (replaces deprecated @MockBean) — puts mock in Box 3

    @Test
    @WithMockUser(roles = "ADMIN")          // Populates Box 6 SecurityContextHolder ThreadLocal!
    void rejects_invalid_isbn_with_400() throws Exception {
        mvc.perform(post("/api/books").with(csrf())
               .contentType(APPLICATION_JSON)
               .content("""
                        {"title":"Dune","author":"Herbert","isbn":"bad"}"""))
           .andExpect(status().isBadRequest())
           .andExpect(jsonPath("$.errors[0].field").value("isbn"));
    }
}

Level 1B — @DataJpaTest + Testcontainers (Box 3/4 Repo Proxies + Real Postgres)

@DataJpaTest
@AutoConfigureTestDatabase(replace = NONE)  // ★ Do NOT swap in fake H2 — test real Postgres SQL!
@Testcontainers
class BookRepositoryTest {

    @Container @ServiceConnection             // Boot 3.1+: auto-fills Box 1 spring.datasource.url!
    static PostgreSQLContainer<?> db = new PostgreSQLContainer<>("postgres:16-alpine");

    @Autowired BookRepository repo;
    @Autowired TestEntityManager em;

    @Test
    void entity_graph_fetches_author_in_one_query() {
        em.persist(aBookWithAuthor("Dune", "Herbert"));
        em.flush();                         // 1. Force SQL INSERT to Postgres now
        em.clear();                         // 2. ★ Wipe Box 6 PersistenceContext 1st-level cache Map!

        Book loaded = repo.findWithAuthorById(1L).orElseThrow();
        assertThat(loaded.getAuthor().getName()).isEqualTo("Herbert");
    }
}

@SpringBootTest(RANDOM_PORT) All 6 Boxes ~4–10 s A handful of critical end-to-end happy paths proving all 6 Boxes wire together cleanly.

§5Explain it to a 12-year-old

Imagine you built a Lego race car with a motorized engine, steering wheel, and radio remote control. How do you test if the steering gears work?

Way 1 (Plain Unit Test — 0 Boxes): You pick up just the front axle in your hands and twist the gear with your fingers. It takes one second. You don't need batteries, you don't need the remote control, and you don't need to go outside to the driveway.

Way 2 (Slice Test — 1 Box): You connect just the radio receiver to the steering motor on your desk (@WebMvcTest) to prove the remote buttons turn the wheel left and right, without bolting on the heavy engine.

Way 3 (Full Integration Test — All 6 Boxes): You bolt the entire car together, carry it outside to the pavement, turn on everything, and drive a full lap (@SpringBootTest). You definitely want to do one or two full laps before race day! But if you carried the whole car outside every time you changed a single Lego brick, you'd spend all day walking up and down the stairs. And if you have 50 tests to run on the driveway, you don't disassemble and rebuild the car 50 times—you keep the built car parked on the driveway and reuse it (that's Test Context Caching!).

§7In practice — Code Dissection & Derive, Don't Memorize

// ═══ A Shared Base Integration Test that Preserves the Box 3 Context Cache ═══
@SpringBootTest(webEnvironment = WebEnvironment.RANDOM_PORT)
@ActiveProfiles("test")                             // ① Fixed profile across ALL IT classes = 1 cache key!
@Testcontainers
public abstract class AbstractIntegrationTest {

    @Container @ServiceConnection                    // ② static container started ONCE per JVM run
    static final PostgreSQLContainer<?> POSTGRES =
        new PostgreSQLContainer<>("postgres:16-alpine");
}

// ═══ Concrete Test Class Reusing the Cached Box 1–6 Container ═══════════════
class BorrowFlowIT extends AbstractIntegrationTest {

    @Autowired TestRestTemplate rest;               // ③ Sends real HTTP over TCP to Box 5 Tomcat
    @Autowired LoanRepository loans;
    @Autowired BookRepository books;

    @AfterEach                                      // ④ Explicit cleanup! (RANDOM_PORT = different thread)
    void tearDown() {
        loans.deleteAllInBatch();
        books.deleteAllInBatch();
    }

    @Test
    void borrowing_persists_loan_and_returns_201() {
        Book saved = books.save(new Book("9780441013593", "Dune", true));

        ResponseEntity<LoanView> res = rest
            .withBasicAuth("member", "secret")      // ⑤ Passes through real Box 5 SecurityFilterChain
            .postForEntity("/api/loans", new BorrowRequest(saved.getId(), 42L), LoanView.class);

        assertThat(res.getStatusCode()).isEqualTo(HttpStatus.CREATED);
        assertThat(loans.count()).isEqualTo(1);
    }
}
Code Dissection:
① Shared Cache Key: Every subclass of AbstractIntegrationTest has the exact same annotations and profile, so SpringExtension hits the ApplicationContext cache 100% of the time after the first test class.
② Singleton Container: Making POSTGRES static in the base class means Docker boots PostgreSQL once for the entire test run instead of restarting Postgres for every class.
④ Why @AfterEach cleanup instead of @Transactional? Because ③ TestRestTemplate calls Box 5 Tomcat over a real socket on a Tomcat worker thread (Rule 3: separate ThreadLocal transaction).

How to Think in Interviews — Derive, Don't Memorize

Classic Interview QuestionDerive the Answer in 10 Seconds from the 6-Box Map & 3 Rules
"Why did our test suite slow down from 30 seconds to 10 minutes as the project grew?" Look at Box 3 Context Cache Map: Someone used different @MockitoBean fields, @TestPropertySource, or @DirtiesContext across test classes. Each unique combination creates a new cache key in Map<MergedContextConfiguration, ApplicationContext>, forcing Spring to rebuild Boxes 1–6 from scratch dozens of times.
"What is the difference between @Mock and @MockitoBean (formerly @MockBean)?" Look at Box 3 (singletonObjects): Plain Mockito @Mock creates a mock object in your test with 0 Boxes started. @MockitoBean reaches inside Box 2 & Box 3 to replace a real Spring Bean definition inside the ApplicationContext Warehouse—and alters the Context Cache key!
"Why did my @DataJpaTest pass even though my SQL @Query has a syntax error or N+1 bug?" Look at Box 6 (PersistenceContext Map<EntityKey, Object>): You called em.persist(entity) and then queried in the same transaction without calling em.flush(); em.clear();. Hibernate returned the entity straight from its in-memory 1st-level cache Map without running the SELECT!
"I put @Transactional on my @SpringBootTest(RANDOM_PORT) test, why didn't it roll back the database?" Apply Rule 3 (Where State Lives — ThreadLocal): The test runs on the JUnit thread, while RANDOM_PORT handles the HTTP request on a Box 5 Tomcat worker thread. The Tomcat thread opens and commits its own independent ThreadLocal transaction before returning the HTTP 200 response!
Try This / Predict the Output:
Suppose you have 10 @SpringBootTest classes. Every single one of them declares a different @MockitoBean (Class 1 mocks EmailClient, Class 2 mocks SmsClient, Class 3 mocks both, etc.).
Question: How many times will Spring Boot run Phase 1 Startup (Boxes 1–6)? How can you fix it so Phase 1 runs only once?
Answer: It will boot Boxes 1–6 10 separate times because the set of @MockitoBean definitions is part of the MergedContextConfiguration cache key! Fix it by moving common mocks (or a shared @TestConfiguration) into a single base class AbstractIntegrationTest so all 10 classes share the exact same cache key.

§8Pitfalls

Pitfall 1: Using @SpringBootTest to test business logic.
Mechanical cause: Boots all 6 Boxes (scanning, auto-config, Hibernate, Tomcat) to test code that only needed plain Java objects in memory. Push business logic tests down to Level 0 (plain JUnit + constructor injection).
Pitfall 2: Defeating the Box 3 Context Cache with scattered @MockitoBean or @DirtiesContext.
Mechanical cause: SpringExtension keys its cache Map on the exact set of mock beans and properties. Varying them per class causes a cache miss and a full multi-second Phase 1 container rebuild. Turn on logging.level.org.springframework.test.context.cache=DEBUG to see hit/miss counts.
Pitfall 3: Skipping em.flush(); em.clear(); in @DataJpaTest.
Mechanical cause: The JPA PersistenceContext inside Box 6 caches any entity you just saved in the same transaction. Queries by ID hit that in-memory Map and skip the database, hiding broken SQL mappings and lazy-loading bugs.
Pitfall 4: Testing with H2 in-memory DB while running PostgreSQL/MySQL in production.
Mechanical cause: H2 has different SQL syntax, constraint checks, and locking rules. Use Testcontainers + @ServiceConnection and @AutoConfigureTestDatabase(replace = NONE) so Box 3 talks to a real Postgres container.

§9Recap & Glossary / Reference

  • Test by turning on the minimum Boxes needed: 0 Boxes (Plain JUnit) → 1 Slice Box (@WebMvcTest / @DataJpaTest) → All 6 Boxes (@SpringBootTest).
  • Constructor Injection (Lesson 3) is what makes 0-Box unit tests effortless—just call new MyService(fakeRepo).
  • Context Caching keeps Box 3 alive in a static Map<MergedContextConfiguration, ApplicationContext>; changing @MockitoBean or properties per class causes cache misses.
  • In @DataJpaTest, always call em.flush(); em.clear(); before querying so Box 6's 1st-level cache doesn't fake the result.
  • Rule 3 (ThreadLocal): @Transactional rolls back MockMvc (same thread) but never rolls back RANDOM_PORT (separate Box 5 Tomcat thread).

Glossary

Test Slice
A partial ApplicationContext that filters Box 2 (BeanDefinitions) to start only one layer (e.g., web in @WebMvcTest or JPA in @DataJpaTest).
Context Caching
Spring Test's mechanism that stores booted ApplicationContext instances in a static Map keyed by MergedContextConfiguration to avoid redundant startups.
MockMvc
In-memory test client that invokes Box 5 Filters and Box 6 DispatcherServlet directly on the test thread without opening a network port.
@MockitoBean
Spring Framework 6.2+ / Boot 3.4+ annotation (replacing @MockBean) that replaces or inserts a Mockito mock into Box 3's bean registry.
TestEntityManager
Helper in @DataJpaTest for setting up JPA test rows and calling flush() and clear() on the persistence context.
Testcontainers & @ServiceConnection
Library that starts real Docker databases for tests; @ServiceConnection automatically wires the container's dynamic host/port into Box 1 (Environment).
